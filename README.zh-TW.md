# RiceHub

**繁體中文** · [English](README.md)

RiceHub 會把你正在看的 GitHub 儲存庫，變成一份結構化的分析提示詞，然後交給你選定的 AI 代理。

重點在提示詞。RiceHub 會辨識儲存庫頁面、把網址正規化成標準形式、擋掉不是儲存庫的路徑、把儲存庫名稱和頁面標題當成不可信的文字而不是指令，再依你勾選的項目組成一份請求。開啟代理是最後一步，不是全部。

在儲存庫頁面按下面板，代理就會開起來、提示詞已經寫好。你看過、想改就改，然後自己按 Enter。報告留在那個對話裡。

RiceHub 不會抓取儲存庫內容、不判斷儲存庫是公開或私有、不替你送出提示詞、不取回結果，也不儲存任何儲存庫資料。

## 瀏覽器支援

| 瀏覽器 | 狀態 |
|---|---|
| Firefox | 已在實際的瀏覽器設定檔驗證過 |
| Chrome 95+ | 有做，但還沒有人在瀏覽器裡實際驗證 |
| Edge | 已驗證：安裝、設定頁、GitHub 上的面板 |

Chrome 寫成「有做」而不是「支援」，是因為到目前為止沒有人在它裡面真的載入 RiceHub 走過一遍，在那之前請當成實驗性質。Edge 則是用比較痛的方式驗證的——懸浮按鈕的圖在那裡載入不出來，也因此才發現 Chromium 解析注入樣式表裡相對路徑的方式跟 Firefox 不一樣。

## 安裝

RiceHub 還沒有上架，所以要用未封裝的方式載入。

**Firefox**

1. 打開 `about:debugging`。
2. 選 **This Firefox**（這個 Firefox）。
3. 選 **Load Temporary Add-on…**（載入臨時附加元件）。
4. 選這個專案裡的 `manifest.json`。

臨時附加元件在 Firefox 關掉之後就會消失，所以重開瀏覽器要再做一次。

**Chrome 或 Edge**

1. 打開 `chrome://extensions` 或 `edge://extensions`。
2. 打開 **開發人員模式**。
3. 選 **載入未封裝項目**，然後選這個專案的資料夾。

裝好之後打開套件的設定頁，選一個目的地。

## 設定

**目的地。** Claude 桌面版、Codex 桌面版，或你自己填的 HTTPS 網址。自訂網址是一個樣板，裡面要剛好包含一個 `{prompt}`，而且不能放在主機名稱那一段。

**語言。** 同時套用到設定頁本身，以及你要求分析時使用的語言。

**懸浮按鈕。** 可以調大小，三個目的地各有一個顏色。按鈕外圈的顏色就是按下去會開哪一個代理——**不用打開這一頁就知道等一下會用哪個**。滑鼠移到按鈕上、或用螢幕閱讀器讀它，會直接說出那個目的地的名字，以及按下去會送出什麼：這個儲存庫的網址和頁面標題。按鈕可以拖到頁面任何地方，位置會被記住；方向鍵可以微調。預設在左下角，那是儲存庫頁面上內容最少的角落。

**分析項目。** 勾選報告要涵蓋哪些面向。每一項底下有一個兩列的輸入框：留空就用預設的問法，想換個問法就自己寫。

**自訂問法盡量寫短。** 提示詞是包在那條開啟代理的連結裡送出去的，而那條連結有長度上限。中文每個字佔掉的長度大約是英文的九倍——因為每個中文字會被編碼成三個位元組、也就是九個字元。實測：整頁英文問法大約是 1,500 字元的連結，同樣內容換成中文超過 14,000 字元。**超過 7,500 字元時 RiceHub 會擋下來並在按鈕上說明**，而不是讓代理收到一個少了最後幾個問題的請求。

## 指令

```sh
npm test
```

用 Node 內建的測試執行器跑完整測試。這個專案沒有任何相依套件，也沒有建置步驟。

## 疑難排解

按了按鈕卻沒有任何反應時：

1. **先確認你選的桌面版有裝。** 在網址列直接測 `claude://claude.ai/new?q=RiceHub%20test` 或 `codex://threads/new?prompt=RiceHub%20test`。如果對應的應用程式沒有打開，代表它的協定處理程式不可用——先把那個註冊修好，再回頭查 RiceHub。
2. **瀏覽器如果跳出確認視窗，要允許它開啟外部應用程式。**
3. **換一個內建目的地再試一次。** 如果一個開得起來、另一個開不起來，問題邊界大概就在開不起來的那個應用程式的協定處理程式。
4. **改過本機的擴充套件檔案之後**，要重新載入未封裝的套件，也要重新整理 GitHub 的分頁。

**代理有開起來，但輸入框是空的：**

這件事在 2026-08-04 實測過：開啟一個桌面 deep link、把輸入框清空、再開一次**完全相同**的連結，輸入框是空的；同一個連結**尾端多幾個空白**，文字就出現了。代理會把處理過的連結當成重複請求。

RiceHub 現在會在每次桌面啟動的提示詞尾端，補上少量、每次不同的空白，讓任兩次啟動在文字上都不相同。**自訂的 HTTPS 目的地維持你設定的原樣**——別人的服務要收到什麼，不是這個擴充套件該替它決定的。如果還是遇到空白輸入框，先從這段補空白的邏輯查起。

關於 Codex：[`src/button.js`](src/button.js) 只在使用者真的點擊的當下，才把產生出來的連結放進 `href`，接著在下一個 task 就清掉。這樣既不會延遲原生連結的啟動，也不會讓自訂的提示詞指示留在 GitHub 的 DOM 裡。

## 設計約束

- Manifest V3，優先在 Windows 驗證，沒有建置步驟。
- 靜態 content script 只跑在 `https://github.com/*`，不要 `<all_urls>`。
- 只公開一個 web-accessible 資源，就是懸浮按鈕那張圖，而且只公開給 `https://github.com/*`。Chromium 需要這個宣告，Firefox 不需要。
- `storage` 只放設定，絕不放憑證、儲存庫網址、提示詞或結果。
- 內建的桌面協定是寫死的；自訂目的地只接受 HTTPS。
- 儲存庫的中繼資料與內容一律視為不可信的提示詞資料。
- 「Open request sent」（已送出開啟要求）是我們敢做的最強宣稱——**協定送達與否是觀察不到的**，所以不會說成「已開啟」。

產品研究、威脅模型與決策紀錄不放在這個儲存庫裡。
